# Agilex 3 C-Series Development Kit JTAG Design Example
This directory contains the peripheral Platform Designer system, Quartus project assignments, and build scripts for deploying the FPGA AI Suite IP (CoreDLA) on the [Altera Agilex 3 C-Series Development Kit](https://www.intel.com/content/www/us/en/products/details/fpga/development-kits/agilex/a3y135b.html). Typically, the build scripts in this directory should be invoked via CoreDLA's `dla_build_example_design.py` script.

## Overview of the Design Example
This design example provides early access to CoreDLA features on Agilex 3 C-series, such as the DSP Tensor Mode. It supports one CoreDLA instance. Given the lack of PCIe on the development kit, this design example relies on a JTAG-Avalon IP to allow an x86 host to access the DDR memory and CoreDLA's CSR registers. The software runtime allows the host to access the CSR and DDR memory of the design example via Altera System Console.

### Clock Domains
There are 3 primary clock domains in this design example:
1. DLA Clock
2. JTAG Clock
3. EMIF Clock

The DLA Clock domain includes the CoreDLA IP's internal datapath, and it is hardcoded at 150 MHz in the script ed_zero.tcl. The JTAG Clock domain includes the JTAG-Avalon Bridge IP and EMIF's AXI4-Lite Initiator IP. It is configured at 100 MHz. Both the DLA Clock and JTAG Clock are produced by an IOPLL IP in the design, and the reference clock frequency of the PLL is 100 MHz. The DLA Clock is hardcoded to 150 MHz.

The EMIF Clock domain is provided by another IOPLL within the EMIF IP. It includes the datapath from EMIF to CoreDLA as well as the DMA block in CoreDLA.

### Reset Domains
The CoreDLA IP sees an active-low reset generated by the EMIF IP. This reset is synchronous to the EMIF clock. EMIF releases this reset when the calibration routine is done and the FPGA fabric has been released from reset. The FPGA fabric reset occurs either when the Reset Bridge IP issues a reset, or when the user asserts a reset via the FPGA's reset pin. A Reset Handler IP is introduced to generate the FPGA fabric reset from Reset Bridge IP and the reset pin.

### External Memory Setting
This design uses the 2GB 2133 Mb/s x32 LPDDR4 interface on IO Bank 2A on the A3CY135BM16AE6S FPGA. The EMIF IP is configured in fabric-synchronous mode, forcing CoreDLA's DDR interface to use the clock generated by EMIF, which is set at 133.33 MHz, one-eighth of the LPDDR4 interface frequency.

### Memory Address Mapping
As seen from the JTAG-Avalon IP, address range 0x0 to 0x7FFFFFFF is allocated to the DDR memory, address range 0x80000000 to 0x80000FFF is allocated to the CSRs on the CoreDLA IP, and address range 0x80008000 to 0x80008FFF is reseved for a timer IP clocked by the DLA clock, which is used by hosts to determine by frequency of the DLA clock. The addressable range allocated to the DDR memory is smaller than the 8GB capacity of the DDR memory, since the JTAG-Avalon IP only supports addressable range up to 4GB.

When changing the memory offsets and addressable ranges, several locations in the code base need to be adjusted:
1. The address offsets and ranges in the Platform Designer system. These are defined in the routine "do_create_system" in the Tcl script "ed_zero.tcl" in this directory.
2. The address offsets and ranges requested in the System-Console Tcl script. This script is at \<runtime directory root\>/coredla_device/mmd/system_console/system_console_script.tcl.
3. The address offsets and ranges defined as macros in the MMD definition of runtime. The source file is at \<runtime directory root\>/coredla_device/mmd/system_console/mmd_wrapper.cpp.

## Hardware and Software Prerequisites
### Software Requirements
Customers should install FPGA AI Suite 2026.3 Release and OpenVINO 2024.6 according to the steps in the [FPGA AI Suite Getting Started Guide](https://www.intel.com/content/www/us/en/docs/programmable/768970.html).
Additional requirements:
1. Quartus Prime Suite Pro 26.3 with Agilex 3 C-Series device support.
2. Quartus Prime Programmer and System Console.
3. Third-party C++ libraries: gflags 2.2.2 and Boost 1.85

### FPGA Requirements
1. Set up the Agilex 3 FPGA C-Series Development Kit for JTAG USB-Blaster programming. DIP switch SW4[4:1] on the carrier board should be set to [OFF, OFF, OFF, OFF] to allow for SOF programming via JTAG.
2. Set up the necessary USB port rules and permissions on the host according to the [Intel FPGA Download Cable II User Guide](https://www.intel.com/content/www/us/en/docs/programmable/683719/current/setting-up-the.html)

## Building the Design Example and Running Inference on the Agilex 3 FPGA C-Series Development Kit
### Setting up a Working Directory
Set up the FPGA AI Suite environment variables according the instructions in [FPGA AI Suite: Getting Started Guide](https://www.intel.com/content/www/us/en/docs/programmable/768970/2024-2/setting-required-environment-variables.html), and create a [working directory](https://www.intel.com/content/www/us/en/docs/programmable/768970/2024-2/creating-a-working-directory.html).

### Building the Design Example Runtime
Build the FPGA AI Suite Runtime using the script *build_runtime.sh* according to the following,
```bash
cd <Working Directory>/runtime
./build_runtime.sh -target_system_console
```
A successful build contains the following objects:
1.	*\<Runtime directory\>/build_Release/libcoreDlaRuntimePlugin.so*: this is a runtime library that contains the APIs for the host to access the FPGA AI Suite IP's registers and memories in the design example.
2.	*\<Runtime directory\>/build_Release/system_console_script.tcl*: The runtime invokes this script via Quartus System Console to set up the JTAG services in order to access the memories and CSR registers in the design example.
3.	*\<Runtime directory\>/build_Release/dla_benchmark/dla_benchmark*: The dla_benchmark application.

### Generating the Design Example FPGA Bitstream
To generate an FPGA bitstream for the Design Example, please use the dla_build_example_design.py script to generate an example design and launch Quartus compilation. The script parameterizes and generates RTL files for the FPGA AI Suite IP, as well as a Quartus Prime Pro Platform Designer system and wrapper RTL file for the entire design example. The script then invokes Quartus Prime Pro to generate the bitstream.

The build flow has been validated on Quartus Prime Pro 26.3 and FPGA AI Suite Release 2026.3
An example build command is
```bash
cd $COREDLA_WORK
dla_build_example_design.py \
    build \
    agx3c_jtag \
    ${COREDLA_ROOT}/example_architectures/AGX3_Small_NoSoftmax.arch
```

This example creates the bitstream file at
```bash
${COREDLA_WORK}/build_platform/AGX3_Small_NoSoftmax.sof
```

### Programming the FPGA
Make sure the USB-JTAG connection and port permissions are set up as described in the Section [FPGA Requirements](#markdown-header-fpga-requirements). Then use Quartus Prime Programmer to configure the FPGA with the bitstream generated in the previous step:
```bash
cd ${COREDLA_WORK}/build_platform
quartus_pgm -c 1 -m jtag -o "p;AGX3_Small_NoSoftmax.sof"
```
### Preparing the Graphs for Inference with FPGA AI Suite
Before running any demonstration applications, customers must convert the trained model to the Inference Engine format (.xml, .bin) with the OpenVINO Model Optimizer. For details on creating the .bin/.xml files, please refer to the [FPGA AI Suite Getting Started Guide](https://www.intel.com/content/www/us/en/docs/programmable/768970.html).

Next, the network as described in the .xml and .bin files (created by the Model Optimizer) is compiled for a specific FPGA AI Suite architecture file by using the FPGA AI Suite compiler. The FPGA AI Suite compiler compiles the network and exports it to a .aot file that uses the same .aot format as required by the OpenVINO Inference Engine. This .aot file created by the compiler contains the compiled network parameters for all the target devices (FPGA, CPU, or both) along with the weights and biases. The inference application imports this file at runtime.

The FPGA AI Suite compiler can also compile the graph and provide estimated area or performance metrics for a given architecture file or produce an optimized architecture file.
For more details about the FPGA AI Suite compiler, refer to the [FPGA AI Suite Compiler Reference Manual](https://www.intel.com/content/www/us/en/docs/programmable/768972.html).

### Performing Inference on an Agilex 3 C-Series Development Kit with the dla_benchmark Application
Assuming the bitstream file is located at $COREDLA_WORK/demo/platform/build_agx3_jtag_ed/AGX3_Generic.sof and has been programmed on the FPGA, then customers can use the following Linux shell command to perform inference on the FPGA development kit with the dla_benchmark application:

```bash
RUNTIME_PATH=<PATH to FPGA AI Suite Runtime Build Directory>
MODEL=<PATH to OpenVINO graph XML file, the BIN file must be in the same directory>
DLA_SOF_PATH=$COREDLA_WORK/build_platform/AGX3_Small_NoSoftmax.sof\
${RUNTIME_PATH}/dla_benchmark/dla_benchmark\
-b=1\
-m=${MODEL}\
-d=HETERO:FPGA,CPU\
-i <path_to>/images/\
-niter=2 --plugins=${RUNTIME_PATH}/plugins.xml\
-arch_file= $COREDLA_ROOT/example_architectures/AGX3_Small_NoSoftmax.arch\
-api=async\
-perf_est\
-nireq=1 -dump_output -report_lsu_counters -enable_early_access
```
Depending on the color channel required by the model, the flag "-bgr" may also need to be included to obtain correct inference results.

The FPGA AI Suite Runtime for this design example needs the location of the bitstream file and the System Console Tcl script to properly claim JTAG services before launching inference. The default bitstream path is top.sof in the working directory, and the default Tcl script path is *\<PATH to FPGA AI Suite Runtime Build Directory\>/system_console_script.tcl*. To override these paths, please set the *DLA_SYSCON_SOURCE_FILE* and *DLA_SOF_PATH* environment variables respectively.

For more information about the dla_benchmark, please refer to [Performing Accelerated Inference with the dla_benchmark Application](https://www.intel.com/content/www/us/en/docs/programmable/768977/2024-2/performing-accelerated-inference-with.html)

### Known Issues and Limitations
1.	The number of inference request (-nireq) must be 1 when running dla_benchmark with the Agilex 3 C-Series JTAG Example Design.
2.	The USB-JTAG connection between the host and the FPGA is relatively slow, so the system throughput is much lower than both the measured and estimated IP throughputs per instance.
